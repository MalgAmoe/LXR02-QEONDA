# Building and verifying QEONDA

All commands below run from the repository root. To install a published image without
compiling, see [the README](../README.md#download-and-install).

Current local firmware/build version is **0.2**, not a published release.
Output filenames use **V0.2**.

## Requirements

- CMake 3.21 or newer, Ninja and Python 3.
- [Arm GNU Toolchain](https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads)
  **14.3.rel1 (GCC 14.3.1)**, the reference compiler used for current firmware and CI.
  Select the `arm-none-eabi` package for your host, including its C library.
- Clang for host tests, separate from the ARM compiler. Use the native Clang
  host-test preset for the supported sanitizer/test configuration.

Put the Arm toolchain's `bin` directory on PATH so both CMake and post-link tools such
as `arm-none-eabi-objcopy` can find it. Check with `arm-none-eabi-gcc --version`.
A compiler-only package without the target C library is insufficient.

## Normal firmware

```sh
cmake --preset release
cmake --build --preset release --parallel 4
python3 tests/check_fm_arm_codegen.py build/release
python3 cmake/tools/verify_release.py build/release
```

If needed, configure with `-DARM_TOOLCHAIN_DIR=/path/to/toolchain/bin`; also keep that
folder on PATH for post-link commands. If changing compiler versions, use a fresh build
directory rather than reusing a cache configured for another compiler.

Outputs in `build/release/` include:

- `LXR_QEONDA_V0.2.img`: SD-card application update.
- `LXR_V2_STM32F765.bin`: raw application payload, not the SD update file.
- `LXR_V2_STM32F765.elf`: linked firmware for inspection.
- `SHA256SUMS`: generated by the verification command, for the update image.
- `release-metadata.json`: CMake-generated version and exact image/payload filenames.
  The validator and release CI consume this file rather than searching for images.
  Reconfigure before verification; old neighboring images are not selected.

The verifier checks image magic, payload length/alignment, checksum, equality with the
BIN payload and absence of measurement definitions in the compile commands. It does
not certify hardware behavior. The FM check verifies target instructions relied on by
the synthesis implementation.

Release builds target Cortex-M7 hard-float FPv5-D16 with O3/fast-math/reciprocal-math;
individual files can have additional options. Inspect `compile_commands.json` when
investigating generated code. Changing optimisation or compiler versions can affect
sound, timing and placement. Same version labels do not imply identical images; retain
the source revision and image SHA-256. Cross-platform byte-identical builds are not promised.

## Host tests

```sh
export CC=clang
cmake --preset host-tests
cmake --build --preset host-tests --parallel 4
ctest --preset host-tests
```

See [the test guide](../tests/README.md) for harness details and sanitizer requirements.
Tests use the computer's native compiler, not the ARM toolchain. Passing host tests and
an ARM build does not measure device stack margin, worst-case audio deadlines, SD-card
latency or MIDI interoperability. Changes affecting those areas need suitable hardware
checks as well.

## Other build options

- `cmake --preset debug`: O3 with debugging symbols, not an unoptimised audio engine.
- `-DLXR_GENERATE_LISTING=ON`: generate a disassembly listing.

Audio is always normalized float32 (original sample / 32768) with padded 24-bit
output on both stereo pairs and
per-operation mix clipping. Original int16 waveform tables and uint32 phases
remain unchanged. No audio variant switches are supported; use a fresh build
directory rather than an old variant cache.

Run the float target check alongside the FM check:

```sh
python3 tests/check_audio_float32_arm.py build/release
```

Historical experiment reports: [transport](AUDIO-24BIT.md),
[float32](AUDIO-FLOAT32.md), [mix clipping](AUDIO-FLOAT32-CLIP.md). Current normalization boundaries and
verification: [AUDIO-NORMALIZED](AUDIO-NORMALIZED.md).
Their old variant commands are not current build modes.

For normal updates use only the application `.img`. These instructions do not require
building or replacing the bootloader.

Project timing instrumentation has been removed. Historical diagnostic evidence is
retained in [PROJECT-MEASUREMENT](PROJECT-MEASUREMENT.md); its old build commands
are not supported by the current source.
